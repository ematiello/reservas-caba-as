# Error log panel and dev data cleanup

Objective: a platform admin screen that audits the errors the system raises, plus a cleanup of the
test data left in the dev project. Branch `feat/gestion-propietario-superadmin` (same branch, new
work units). Delivery: single PR, work-unit commits. Runner: Vitest (unit and DB tests against dev)
and Playwright.

## Specs

- S1 "implementemos tambien dentro del sistema un panel de auditoria de logs de errores"
- S2 "Limpiemos de dev (134 usuarios de prueba, 17 organizaciones, 5 planes, el feriado nacional y los registros de auditoria)"
- S3 "Solo deja mi usuario superadmin." (earlier message, same cleanup: only `edgardomatiello@gmail.com` stays)

Decisions taken without asking (the user prefers to be told at the end, not asked):

- S1: errors are grouped by a fingerprint (source, route, normalized message); a repeat increments a
  counter and the last-seen time instead of adding a row, so a flood cannot fill the table. A
  resolved error that happens again reopens.
- S1: server errors are captured by `src/instrumentation.ts` (`onRequestError`); browser errors by an
  error boundary that reports through a server action. Both write through the server-only
  `service_role` client (an internal task); the table has no insert policy for any user.
- S1: only the platform admin reads and manages the log (`/admin/errores`); statuses are open,
  resolved and ignored, and each change is written to the audit log.
- S1: no request bodies, headers, cookies or query strings are stored; messages and stacks are
  sanitized (emails, long digit runs, tokens and keys are replaced) and truncated.
- S1: resolved errors are purged after 90 days and any error after 180 days (`pg_cron`).
- S2/S3: kept are the user `edgardomatiello@gmail.com`, `platform_settings` and the amenities
  catalog (structure, not test data). Deleted are everything else: users, organizations with all
  their data, plans, the national holiday, audit rows and the files in the `media` bucket.
